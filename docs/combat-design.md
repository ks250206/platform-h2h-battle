# 戦闘システム設計

この文書はBRAMBLEの試作に実装したルールを説明します。数値はバランス調整の出発点です。定数の中心は [`src/game/tuning.ts`](../src/game/tuning.ts)、状態遷移と試合処理は [`src/game/engine.ts`](../src/game/engine.ts) にあります。

## 1. 戦闘の狙い

大剣の長い前隙・後隙に、ためキャンセルと方向を保つステップを組み合わせています。相手のためを見てすぐ回避すればフェイントに捕まり、攻撃を確定させれば空振りを狙われる、という読み合いが中心です。振りかぶり中にもキャンセルできますが、確定した時点で攻撃のスタミナは全額払っており、遅く止めるほど取消硬直が長くなるため、空振りを避けても隙は残ります。

ガードはありません。通常移動で間合いを外す、短い無敵を合わせる、空中へ逃げる、先に攻撃を当てる、という選択肢を使います。つかみは、相手を危険な位置へ動かす役割です。

## 2. 状態とキャンセル

攻撃の基本経路は `idle → charge → windup → active → recovery → idle` です。

| 状態                   | できること・制約                                                               |
| ---------------------- | ------------------------------------------------------------------------------ |
| `idle` / 待機          | 移動、照準、攻撃開始、地上ジャンプ、ステップ（空中は1回）、地上つかみ          |
| `charge` / ため        | 低速移動、制限付き旋回、通常キャンセル、ステップへのキャンセル                 |
| `windup` / 前隙        | 攻撃確定後。技は固定、照準へは低速で旋回。判定が出るまで通常キャンセルのみ可能 |
| `active` / 判定中      | 剣の当たり判定が有効。各技の踏み込みや上昇が発生                               |
| `recovery` / 後隙      | 攻撃・回避・ジャンプへキャンセル不可。空中のみ弱い移動入力が可能               |
| `cancel` / 取消硬直    | ためからは0.12秒、前隙からは0.12〜0.32秒後に待機へ戻る                         |
| `step` / ステップ      | 移動方向と身体の向きを固定。指定した区間だけ無敵。空中では滞空ごとに1回        |
| `hitstun` / 被弾硬直   | 吹っ飛び中。ヒットストップ終了時にDIを反映                                     |
| `clash` / 相殺         | 0.28秒の反動硬直                                                               |
| `grab` / つかみ試行    | 狭い前方判定。失敗時は0.70秒の後隙                                             |
| `throw` / 投げ準備     | 短時間保持し、移動入力で投げる方向を選ぶ                                       |
| `grabbed` / つかまれ中 | 相手の前方に拘束。投げ、相手の被弾・退場などで解除                             |
| `dead` / 退場          | 残機があれば1.4秒後に復帰、なければ脱落。稽古では1.5秒後に復活                 |

着地しても攻撃の後隙は解除しません。攻撃後隙をジャンプやステップで上書きすることもできません。

### ためとフェイント

- 攻撃ボタンを押すと、スタミナを**10先払い**してために入ります。開始時にはその技の総消費量を持っている必要があります。
- 0.90秒で最大ため。ボタンを放すか、保持が1.30秒に達すると攻撃を確定します。
- 確定時に残りのスタミナを支払い、技固有の前隙を最初から開始します。ため時間で前隙が短くなることはありません。
- ため中の `Q` のキャンセルは追加消費なしですが、先払いした10は返却しません。取消硬直は0.12秒です。
- 前隙（振りかぶり中）も、判定が出る直前まで `Q` でキャンセルできます。判定中と後隙ではキャンセルできません。
- 前隙からのキャンセルでは、取消硬直が `RULES.cancelDuration + RULES.windupCancelPenalty × 前隙の進行度` になります。振りかぶった直後なら0.12秒、判定直前なら0.32秒です。動き出した剣ほど止めるのに時間がかかります。
- 前隙からのキャンセルではスタミナを返却しません。先払いの10と確定時に支払った残りを合わせた、攻撃の総消費がそのまま失われます。
- 前隙からステップへは移れません。ステップへ移れるのは、ため中だけです。
- ためからステップに移る場合は、追加で25消費します。先払いを含めた総消費は35。ステップ開始前に0.10秒の無防備な遅延があります。
- 旋回速度は待機中が毎秒20rad（`RULES.idleTurnRate`）、ため中が毎秒3.6rad（`chargeTurnRate`）、前隙が毎秒2.6rad（`windupTurnRate`）です。攻撃を確定しても判定が出るまでは照準へ向き直り続け、判定が出た時点（`active`）で向きが固まり、後隙が終わるまで旋回しません。ステップ中も旋回しません。
- 突きの踏み込みと振り上げの上昇は、判定が出た瞬間の向きへ進みます。前隙で向き直した分だけ進路も変わります。
- CPUの前隙中の旋回速度は、強さに応じて `windupTurnRate` の0倍・0.5倍・1倍です（第9節）。

スタミナ回復待ち時間は、ため中・前隙のどちらのキャンセルでも再設定します。フェイントを繰り返して無料で安全を確保することはできません。

### 先行入力

硬直が解ける直前の短い入力を受け付けます。対象は攻撃4種・ステップ・ジャンプ・つかみで、キャンセルは対象外です。

- 受付時間は**0.10秒**（`RULES.inputBuffer`、60Hzの固定更新で6ティック、`INPUT_BUFFER_TICKS`）。押したティックを0として数え、6ティック目までに実行できるようになれば、その最初のティックに1回だけ発動します。7ティック以上前の入力は破棄され、後から勝手に出ることはありません。0.10秒は大剣の「振ったら最後まで振る」重さを残しつつ、後隙明けを目押しさせない長さです。
- 受け付けるのは、その行動をまだ試せないときだけです（後隙、取消硬直、ステップ中、相殺、被弾硬直、ヒットストップ、つかみ・投げ、空中でのジャンプとつかみ）。試せるティックの入力は従来どおり即座に処理します。
- 着地待ちのジャンプとつかみも、後隙明けと同じく「試せるようになったティックの6ティック前まで」の入力を受け付けます。入力の処理は物理より先に行うため、着地したティックの入力はまだ空中扱いで、実際に発動するのは着地の次のティック（最初に地上で入力を処理するティック）です。そのため着地で解放された入力に限り、破棄を1ティック猶予します（`landingGrace`）。着地ティックの6ティック前の入力は発動し、7ティック前の入力は破棄されます。着地時に後隙などがまだ残っていて、それが明けることで解放される場合は猶予しません。
- 割り込まれる前の入力は捨てます。被弾硬直に入ったとき（`receiveHit`）、つかまれたとき、相殺したとき、ため中・前隙を自分でキャンセルしたときに、それまでの先行入力を破棄します（同じティックに押した入力も含みます）。割り込まれる前の押下が、新しい硬直の明けに勝手に出ることはありません。被弾後のヒットストップ・被弾硬直、つかまれている間、相殺、取消硬直の中で押した入力は、通常どおり保持して明けたティックに発動します。
- 発動は「そのティックに押した」のと同じ扱いです。スタミナが足りなければ通常どおり何も消費せずに失敗し、先行入力も消えます（スタミナの回復を待ち続けません）。後隙や判定中を短縮することはなく、空中ジャンプ・空中つかみの禁止も破りません。空中で使い切った振り上げ・突き・空中回避は、試せるようになった最初のティックに通常どおり失敗して消え、着地まで持ち越して地上技として出ることはありません。
- 攻撃は、発動時にボタンをまだ押していればそのままために入り、離すか1.30秒で確定します。後隙中に押して離していれば、通常のタップと同じく次のティックに確定します（ためはほぼ0）。発動時に別の攻撃ボタンを押し続けていても同じで、先行入力した攻撃がタップとして1回出るだけです（押し続けているほうがために入ったり、2回目が出たりはしません）。1回の押下で攻撃が2回出ることはありません。
- 保持できる先行入力は1つです。新しい押下が古いものを置き換え、受付時間も新しい押下から数え直します。同じティックに複数押して、どれも実行できない場合はステップ＞つかみ＞攻撃＞ジャンプの順で1つだけ残します。実行できる押下が1つでもあれば、そのティックの入力を従来どおり処理して先行入力は捨てます。先行入力があっても、新しく押した入力が常に優先です。
- ステップの方向と照準は、押したときではなく発動したティックのスティックを使います。
- キャンセルは保持もしなければ再生もしません。後隙中や硬直明けに押したキャンセルが次の攻撃を止めることはありません。ため中・前隙のキャンセルは従来どおり押したティックに効きます。
- 経過は固定更新のティックで数えるので、描画が30Hzでも144Hzでも受付時間は同じです。ヒットストップ中も経過は進み、ヒットストップの前やその途中に押した入力が長く残ることはありません。
- 先行入力は人間のプレイヤーだけのもので、プレイヤーごとに独立しています。CPUは毎ティック判断し直すので使いません。一時停止（パッドの切断による一時停止を含む）、退場、復帰、試合終了、再戦、メニューで破棄します。
- 先行入力は押したときの状態（`pressedIn`）を覚えており、取り出しは `takeBuffered` の1か所に集めています。被弾硬直からの受け身のような規則を追加するときは、汎用の再生より先にここでステップを取り出す・捨てることができます。

## 3. 4つの攻撃

以下は無ため時の値です。時間の単位は秒、ダメージは蓄積%への加算値です。

| 技         | 前隙 | 判定持続 | 後隙 | 総スタミナ | ダメージ | 主な役割                                             |
| ---------- | ---: | -------: | ---: | ---------: | -------: | ---------------------------------------------------- |
| 振り下ろし | 0.43 |     0.14 | 0.60 |         25 |       18 | 狭めの前方へ重い一撃。空中ではメテオを狙う           |
| 振り上げ   | 0.38 |     0.22 | 0.62 |         25 |       12 | 対空、斜め前方への上昇、縦の復帰                     |
| 横振り     | 0.35 |     0.18 | 0.48 |         20 |       11 | 前方の扇形。踏み込まず、横への回避を狩る             |
| 突き       | 0.28 |     0.16 | 0.52 |         20 |       10 | 狭い幅と長い前方リーチ。踏み込み、差し返し、横の復帰 |

ため量を0〜1で表すと、ダメージ倍率は `1 + ため量 × 0.65`、吹っ飛び倍率は `1 + ため量 × 0.25` です。最大ためではそれぞれ1.65倍・1.25倍になります。

吹っ飛びは、技の基礎値と**命中後の蓄積%**から求めます。振り下ろしのメテオは、攻撃側・被攻撃側がともに空中の場合に発生し、上下方向の速度を下向きにします。

### 判定

身体は動物の耳や尻尾に左右されない共通の簡略判定です。剣は技ごとの前方距離・横幅・高度差で判定し、横振りは扇形として扱います。

攻撃確定ごとに命中済みの相手を記録し、**同じ一振りは同じ相手に1回だけ命中**します。乱闘では1回の横振りが複数の相手に当たることがあります。

## 4. スタミナとステップ

| 項目             | 初期値 |
| ---------------- | -----: |
| 最大スタミナ     |    100 |
| 消費後の回復待ち | 0.50秒 |
| 回復速度         | 毎秒30 |
| 通常ステップ     |     25 |
| つかみ           |     18 |
| 歩行・ジャンプ   |      0 |

スタミナは待機中・被弾硬直中に回復します。ため、攻撃、後隙、ステップの最中は回復しません。ヒットストップ中は当事者の回復処理も停止します。

不足している行動は開始できませんが、歩行と地上ジャンプは残ります。スタミナを使い切ると、攻撃後に回避する余力がなくなります。

ステップの全体時間は0.30秒です。

| 開始からの時間 | 状態             |
| -------------- | ---------------- |
| 0.00〜0.08秒   | 無敵なし         |
| 0.08〜0.20秒   | 攻撃に対して無敵 |
| 0.20〜0.30秒   | 無敵なし         |

入力方向へ移動しながら身体の向きを維持します。方向入力がなければ前方へ進みます。ためからのステップには、この時間配分の前に0.10秒の遅延が入ります。エリア外ゲージとエリア外ダメージはステップで回避できません。

### 空中回避

ステップは空中でも、滞空1回につき1回使えます（`airStepUsed`）。

- 消費（25、ためからは追加で25）、全体時間、無敵区間、移動速度は地上のステップと同じで、ほぼ同じ距離（約2.6）を進みます。
- 移動が始まった時点で上下速度を毎秒1.5（`RULES.airStepHover`）以上に引き上げ、移動中は上下速度が毎秒1.5以下の間だけ重力を0.35倍（`RULES.airStepGravity`）にします。高さをほとんど失わずに横へ進みます。
- 上昇中の速度は下げず、毎秒1.5より速く上昇している間は通常の重力のままです。ジャンプや振り上げの直後に空中回避しても、到達する高さはほぼ変わりません。
- ためからの空中回避では、0.10秒の遅延の間は通常の重力で落ち、移動が始まってから浮きます。
- 使用権は床の上への正規の着地でのみ回復します。空中で被弾しても回復しません。
- 空中の振り上げ・突きの使用権とは独立しています。空中回避がそれらを回復・消費することはなく、逆も同じです。
- 地上で始めたステップが足場の外へ出た場合は空中回避として扱わず、使用権を消費せずに通常の重力で落ちます。その後の空中回避は使えます。

## 5. ジャンプと復帰

地上の待機状態から1回ジャンプできます。空中ジャンプはありません。

空中の**振り上げ、突き、空中回避（第4節）は、それぞれ1回**使用できます。以下は振り上げと突きの使用権の規則です。空中回避の規則は第4節を参照してください。

振り上げと突きの使用権は攻撃確定時に消費し、床の上へ正規に着地したときだけ回復します。空中で被弾しても、ためを再入力しても回復しません。ため中のキャンセルでは、空中使用権を消費しません。空中で攻撃を確定した後に前隙でキャンセルしても、消費した使用権は戻りません。

地上からの振り上げも上昇に使用するため、その滞空中の振り上げは使用済みです。地上の突きで足場の外へ出た場合も、その滞空中の突きを使用済みとして扱います。

復帰の手段は3つです。空中の振り上げは上昇、突きは水平移動と落下速度の緩和、空中回避は短い無敵を伴うほぼ水平の移動を担い、使う順番と向きを選べます。どれもスタミナを使うため、使い切った状態では戻れません。床の下から側面に触れるだけでは着地扱いにしません。

## 6. 相殺・ヒットストップ・DI

### 相殺

同時に攻撃中の剣の判定同士が接触すると相殺します。通常の被弾処理より先に全組み合わせを調べ、相殺した攻撃の通常ダメージを止めます。

相殺した双方には0.11秒のヒットストップ、0.28秒の反動硬直、後方への小さな押し戻しが入ります。単に近くで同時に攻撃しているだけでは相殺しません。横振りは複数の剣線分で近似しています。

相殺しない攻撃の命中候補も一度集めてから適用し、同時命中の打ち合いを残します。乱闘の同時攻撃は安定したID順で処理します。

### ヒットストップと時計

通常命中のヒットストップは0.085秒で、最大ためでは0.110秒になります。停止するのは当事者のモーション、状態時間、物理移動、スタミナ処理です。乱闘のほかの参加者は動き続けます。

**試合時計、足場縮小、爆撃、エリア外ダメージと5秒ゲージは進み続けます。** ヒットストップを利用してエリア外の退場を先送りにはできません。一方、ゲームの一時停止では試合全体の時間が止まります。

### DI

被弾で決まった吹っ飛びは、ヒットストップ終了時の移動入力を使って確定します。水平の角度だけを最大±15°変更し、水平速度の大きさと上下速度は保持します。

純粋な上下方向への吹っ飛びに、DIで新しい水平速度を加えることはありません。メテオを上向きに変えることもできません。

## 7. つかみと投げ

つかみは地上専用。発生0.20秒、判定持続0.09秒、射程1.25で、正面の狭い範囲にだけ当たります。空振りすると0.70秒の後隙があります。

成功後は0.45秒保持し、その間の移動入力で投げ方向を選べます。方向入力がなければ前方へ投げます。投げのダメージは6、投げた側の後隙は0.40秒です。

投げの目的は位置の変更です。セーフゾーン外や崩壊する外周へ向けて使えます。つかんだ側が被弾・退場するなどして行動を継続できなくなった場合、拘束を解除します。

## 8. 足場と環境

通常モードは9×9枚のタイルを敷いた正方形の足場から始まります。1タイルは2ワールド単位、初期の足場は18×18です。

| 仕組み           | 初期仕様                                                         |
| ---------------- | ---------------------------------------------------------------- |
| 外周崩壊         | 32秒で開始。その後22秒ごとに外周1列を除去。4秒前に予告           |
| 最小の足場       | 3×3タイル。足場の半幅3で縮小停止                                 |
| セーフゾーン     | 18秒から有効。縮みながらゆっくり移動し、残った足場の内側に収める |
| エリア外         | 毎秒7%と、毎秒1秒分の退場ゲージを加算                            |
| 安全地帯へ再侵入 | 毎秒2秒分の退場ゲージを回復。蓄積%は減らさない                   |
| 強制退場         | 退場ゲージが5秒分に達したとき                                    |
| 爆撃             | 14秒から11秒間隔。2.1秒の予告後に爆発                            |
| 爆撃数           | 一騎打ちは2か所、乱闘は3か所                                     |
| 爆撃の威力       | 10%と小さな吹っ飛び。短い無敵や十分な高度で回避可能              |
| 風               | 24秒以降の一部時間帯に地上のキャラクターを弱く押す               |

エリア外のルールは**瞬間的な再侵入でリセットする連続5秒タイマーではなく、戻ると徐々に回復するゲージ**です。HUDに現在値を表示します。稽古ではこれらの環境ギミックを無効にします。

上の表は浮遊庭園の値です。ほかのステージは次の節のとおり、崩落の回数、セーフゾーンの動き、風の有無が変わります。

### ステージ

ステージは [`src/game/stages.ts`](../src/game/stages.ts) で定義します（`StageId` は `garden` / `ruins` / `bridges` / `factory`）。1つのステージは床のタイル（中心と幅・奥行きを持つ長方形。種類は床・橋・コンベア）の一覧で、**当たり判定と3Dの床は同じ一覧から作ります**。タイルは中心が残っている正方形（`arena.halfSize`）の内側にある間だけ存在し（`isTileSupported`）、描画はそのタイルだけを表示し、`canStandAt` はそのタイルの上だけを床とします。

| ステージ     | 床                                                                                                              | 開始位置（中心から） | 崩落後の最小の半幅 | セーフゾーン                                                           | 風   |
| ------------ | --------------------------------------------------------------------------------------------------------------- | -------------------: | -----------------: | ---------------------------------------------------------------------- | ---- |
| 浮遊庭園     | 9×9タイルの正方形（穴なし）                                                                                     |                  3.5 |                  3 | 残った足場の内側を漂う。半径は8.4から2.7へ                             | あり |
| 中央穴の遺跡 | 9×9タイルから中央の3×3を除いた環。穴は ±3 の正方形                                                              |                    6 |                  7 | 半径5の円周上を毎秒0.08ラジアンで周回。半径は10.4から3.2へ             | あり |
| 細い橋の回廊 | 四方に4×6の島（中心から5〜9）、中央に4×4の広場（±2）、広場と島を結ぶ幅1.6・長さ3の橋（長さ1の板3枚）            |                    7 |                  9 | 広場から4本の腕を順に往復。外へ出る距離は縮小とともに最大6.2まで伸びる | なし |
| コンベア工場 | 9×9タイルの正方形（穴なし）。中心から2タイル目の環が環状ベルト、奥と手前の端の列がレーン。ベルトの速さは毎秒2.2 |                    6 |                  5 | 浮遊庭園と同じ式                                                       | なし |

- **床の判定:** 穴のないステージ（庭園、工場）は従来どおり、残っている正方形の内側すべてが床です。穴や隙間のあるステージは、残っているタイルの長方形（境界を含む）の和集合が床です。崩落で進む半幅（9・7・5・3）では、両者は描画するタイルと一致します。
- **セーフゾーンの中心は必ず床の上**にあります。遺跡では穴の上に来ず、回廊では広場・橋・島の中心線の上だけを動きます。
- **コンベア:** `conveyorVelocityAt` が位置ごとの速度を返します。接地しているキャラクターは、プレイヤーかCPUか、どの状態（待機、ため、前隙、攻撃、後隙、ステップ、被弾硬直、つかみ）かにかかわらず、毎更新その分だけ運ばれます。空中では運ばれません。ヒットストップ中、一時停止中、カウントダウン中は他の移動と同じく止まります。環状ベルトは奥の辺が+X、+X側の辺が+Z、手前の辺が−X、−X側の辺が−Zへ流れ、角のタイルは次の辺の向きです。奥のレーンは+X、手前のレーンは−Xへ流れ、端で場外へ出ます。稽古でも動きます。
- **爆撃:** 狙う位置の乱数は全ステージ共通で、穴や隙間のあるステージでは最寄りの床（縁から0.4内側）へ移します。
- **開始位置:** 一騎打ちと稽古は −X と +X、乱闘は四方で、すべて中心を向きます。最初の崩落のあとも残る床の上で、コンベアの上は避けます。
- **復帰位置:** 穴のないステージは従来どおりです。穴や隙間のあるステージでは、ステージごとの決まった地点（どの段階でも残る床の上で、縁から0.7以上内側）のうちセーフゾーンの内側にあるものと、ゾーンの中心と周囲8点から最寄りの床へ寄せた地点が候補です。ゾーンが狭いか床から外れていて候補が1つも残らないときは、ゾーンの中心から最寄りの床（縁から0.4内側）を唯一の候補にします（ゾーンの外になることがあります）。候補は必ず1つ以上あります。候補の選び方（爆撃の予告を避け、相手から最も遠い地点）は変わりません。
- **タイトル画面:** ステージを選ぶと、名前・特徴・ギミックごとの扱い（あり ○ / 制限つき △ / なし ×）と説明文を試合前に表示し、背景の足場をそのステージに入れ替えます。

## 9. 試合とCPU

### プレイヤーとCPU

試合の枠は、一騎打ちと稽古が2つ（ID 0〜1）、乱闘が4つ（ID 0〜3）です。どの枠を誰が操作するかは `MatchOptions.controls`（[`src/game/match.ts`](../src/game/match.ts)、キーは枠のID、値は `keyboard` / `pad1`〜`pad4`）で決め、エントリのない枠はCPUです。キーボード（マウスかタッチ操作と合わせて）は1人分、パッドは1台につき1人分で、1つの機器が2つの枠を操作することはありません。枠0（コハク）は常にプレイヤーで、保存値に枠0がなければ空いている最初の機器を割り当てます。どのモードでも、そのモードにある枠ならプレイヤーにできます（稽古の枠1は練習相手）。モードにない枠の割り当ては無視します。

`humanSlots(options, fighterCount)` がその試合のプレイヤーの枠を枠の順に返し、キャラクターを作るときに `Fighter.human`（プレイヤーか）と `Fighter.player`（プレイヤーの中での1始まりの番号、CPUは `null`）を決めます。番号は枠の順なので、枠0は常に `P1` です。たとえば乱闘で枠0・2・3がプレイヤーなら、番号は `1, null, 2, 3` です。どちらも復帰と稽古の作り直しで引き継ぎます。

- プレイヤーのキャラクターはCPUの思考を使いません。入力がなければ（パッドが外れたときなど）立ち止まり、CPUには切り替わりません。前隙中の旋回は常に `windupTurnRate` の1倍です。
- CPUの強さの上書き（`overrides`）はCPUの枠にだけ効きます。
- 試合の開始時には `playableOptions`（[`src/game/matchStore.ts`](../src/game/matchStore.ts)）で、接続されていないパッドの枠をその試合だけCPUにします。枠0のパッドがなければ枠0をキーボードにし、キーボードを使っていた枠をCPUにします。保存した設定は変えません。
- 勝敗と制限時間の規則はプレイヤーとCPUを区別しません。
- スタミナ不足の通知（画面中央の「スタミナ不足」）は共有の表示で誰のことか示せないため、プレイヤーが1人の試合でだけ出します。

### 残機と退場

通常モードは残機制です。残機は試合ごとに1〜5から選び（`MatchOptions.stocks`、初期値3）、全員が同じ数で始めます。床の下へ大きく落下する（高さ−9未満）、外側へ大きく飛び出す（中心から26超）、エリア外ゲージが5秒に達する、のいずれかで退場し、残機を1つ失います。最後に攻撃を当てた相手には撃墜数が入ります。

### 復帰

- 残機が残っていれば、退場から1.4秒後（`RULES.respawnDelay`）に復帰します。待っている間は攻撃・爆撃・つかみ・押し合いの対象にならず、エリア外ゲージも進みません。ロックオンとCPUの狙いからも外れます。
- 復帰位置の候補は、セーフゾーンが有効ならその中心と半径の55%の円周上の8点、有効になる前は足場の中心と半径3の円周上の8点です。候補は足場の端から1以上内側に収めます。未爆発の爆撃の範囲にかからない候補のうち、生きている相手から最も遠い点を選びます。乱数は使いません。
- 高さ6（`RULES.respawnHeight`）から落ちてきます。向きは最寄りの相手です。
- 復帰後2.5秒（`RULES.respawnInvulnerable`）は攻撃・爆撃・つかみを受けません。その間も通常どおり行動できます。
- 状態は新しいキャラクターとして作り直します。蓄積%は0、スタミナは100、エリア外ゲージは0、空中の使用権はすべて回復、状態は待機です。残機、撃墜数、CPUの強さ、プレイヤーかどうかとその番号は引き継ぎます。

### 勝敗と制限時間

残機が残っているキャラクター（復帰待ちを含む）が1人になった時点で、その1人の勝利です。最後の残機を全員が同時に失った場合は引き分けです。

制限時間は `150 + 60 × (残機 − 1)` 秒です（`matchTimeLimit`、`RULES.maxMatchTime` と `RULES.matchTimePerStock`）。1機なら150秒、3機なら270秒、5機なら390秒です。時間切れでは、残機の多いキャラクターが勝ち、同数なら蓄積%の少ないキャラクターが勝ちます。復帰待ちのキャラクターはその命の%をすでに失っているため、0%として比べます。1位と2位の残機が同じで、%の差が0.01未満なら引き分けです。1機の試合はこれまでの1ライフ制と同じ結果になります。

稽古では残機と制限時間を使いません。CPUの相手は動かず、退場したキャラクターは1.5秒後に何度でも復活します。

### CPU

CPUは最寄りの相手（復帰待ちを除く）を狙い、相手との距離、技の状態、足場の端、セーフゾーン、爆撃を見て行動します。ため、ステップ、つかみ、空中復帰も使います。行動の選択には固定シードの乱数を使います。

強さは `AI_LEVELS`（[`src/game/tuning.ts`](../src/game/tuning.ts)）で定義し、よわい（`easy`）・ふつう（`normal`）・つよい（`hard`）の3段階です。

| 項目                                           | よわい        | ふつう                   | つよい                   |
| ---------------------------------------------- | ------------- | ------------------------ | ------------------------ |
| 判断の間隔（`thinkMin` + 乱数 × `thinkRange`） | 0.42〜0.70秒  | 0.18〜0.34秒             | 0.10〜0.18秒             |
| 回避する確率（`dodgeChance`）                  | 0.20          | 0.70                     | 0.90                     |
| 回避を待つ（`dodgeWindow`）                    | 待たない      | 待たない                 | 前隙の残り0.17秒まで     |
| 剣筋を読んだ回避（`smartDodge`）               | なし          | なし                     | あり                     |
| 攻撃に必要なスタミナ（`attackStamina`）        | 45            | 30                       | 30                       |
| ため攻撃にする確率（`chargeChance`）           | 0             | 0.30                     | 0.45                     |
| フェイントする距離（`feintRange`）             | しない        | 2.4                      | 2.8                      |
| 前隙中の旋回（`tracking`）                     | 0倍           | 0.5倍                    | 1倍                      |
| 爆撃に気づく（`bombNotice`）                   | 爆発の0.9秒前 | 予告の直後               | 予告の直後               |
| 復帰の手段                                     | 振り上げ      | 振り上げ・突き・空中回避 | 振り上げ・突き・空中回避 |
| 空振りの取り消し（`cancelWhiffs`）             | なし          | なし                     | あり                     |
| 後隙への反撃（`punishRecovery`）               | なし          | なし                     | あり                     |
| 狙った投げ（`aimedThrows`）                    | なし          | なし                     | あり                     |

- **回避:** 相手が距離3.4以内にいて、その相手が前隙に入ったとき、または気づいている爆撃の爆発まで0.7秒を切ったとき、スタミナが25以上あれば判断のたびに `dodgeChance` の確率で地上ステップします。足場の端では回避しません。気づいた爆撃からは、ステップしなくても歩いて離れます。`dodgeWindow` が有限のCPUは、相手の前隙の残りがその時間を切るまで毎フレーム判断を保留し、前隙中の旋回で追われない終わり際に避けます。
- **回避方向:** `smartDodge` がなければ、横振りには後ろへ、それ以外には横へ避けます。あれば、横振りには相手から離れる方向へ、細い剣筋には剣筋のすでにいる側へ（真正面なら足場の内側へ）、爆撃には爆心から離れる方向へ避けます。
- **攻撃:** 距離3.3以内で `attackStamina` 以上のスタミナがあれば攻撃を選びます。`chargeChance` の確率で0.4〜0.9秒ため、それ以外はすぐ放します。ため中に相手が前隙に入り、`feintRange` 以内なら、ステップへのフェイントを使うことがあります。CPUは空中回避を復帰にだけ使い、回避やフェイントでは地上ステップだけを使います。
- **前隙中の旋回:** `tracking` は `RULES.windupTurnRate` に掛ける倍率です。よわいは振りかぶったら向きを変えません。
- **復帰:** 足場の外の空中では中央へ向かいます。高さ0.8未満で振り上げが残っていれば振り上げ、そうでなければ突きを使い、空中回避は振り上げを使い切って突きも使えないときの最後の手段です（その強さで使える手段だけ）。浮遊庭園以外での復帰は下の「ステージごとの動き」のとおりです。
- **空振りの取り消し:** 前隙の残り時間で旋回できる最大の角度と、突きの踏み込み・振り上げの上昇を見込んでも剣が届かない場合、または判定が出る時点で相手がまだ無敵の場合、前隙をキャンセルします。
- **後隙への反撃:** 後隙中の相手へ近づき、距離と相手の後隙の残りに合わせて、相手が動けるようになる前に当たる技をためずに出します（空中の相手には振り上げ、遠ければ突き、時間があれば振り下ろし、なければ横振り）。
- **狙った投げ:** 投げの距離で足場の端に届くなら最寄りの端へ、届かずセーフゾーンが有効ならゾーンの外へ投げます。

ふつうは従来のCPUの数値をそのまま使います。違いは前隙中の旋回（0.5倍）と、復帰の最後の手段としての空中回避だけです。

#### ステージごとの動き

浮遊庭園のCPUは上のとおりで、これまでと同じ判断をします。穴や隙間のあるステージ（遺跡、回廊）とコンベアのあるステージ（工場）では、どの強さのCPUも次の規則を加えます。

- **道筋（遺跡・回廊）:** 相手やセーフゾーンへは、まっすぐ歩けるならまっすぐ、歩けなければ [`src/game/navigation.ts`](../src/game/navigation.ts) の経路に沿って向かいます。経路は間隔1の格子点（まわり0.45に床がある点）の最短路で、まっすぐ歩ける範囲で先の点へ近道します。相手が穴の上にいれば、最寄りの床で待ちます。
- **足もと（遺跡・回廊）:** 歩く先0.9に床がなければ、床の続く向きへそらします。縁のそば（風のない間は0.45、風のある間は0.7以内に床の切れ目）では攻撃を始めず、先に内側へ戻ります。ためや前隙の途中で縁から0.12以内になったら取り消します。足場の端に近いというだけの理由で中央へ戻る規則は使いません。
- **踏み込みと回避:** 突きの踏み込み（地上1.7、空中3.8）や振り上げの跳び出し（2）の先に床がなければ、届く距離なら振り下ろしか横振りに替え、届かなければ攻撃しません。ためや前隙の途中でそうなった場合（相手が動いた、足場が崩れた）は取り消します。ステップは、進む先（2.9）まで床が続く向き（望んだ向き、左右、逆の順）にだけ使い、なければ使いません。
- **崩落の予告:** 予告が出ている間は、崩れたあとの足場を基準に上の判断をします。崩れる列にいれば、崩れる前に内側へ移ります。
- **復帰:** 最寄りの床（縁から0.6内側）へ向かいます。落ちるまでに空中の移動だけで届くなら何も使いません。届かなければ、空中回避の先（2.3〜2.7）が床ならそれを使い（まっすぐが駄目なら左右に少し振った向きも試す）、高さ0.8未満なら振り上げ、突きは前隙のあとに高さが残り、飛ぶ距離の先が床のときだけ使います（細い橋を飛び越えないため）。使える手段は強さごとの表のとおりです。
- **コンベア（工場）:** ベルトの上では、流される分のうち進みたい向きに直交する成分を打ち消す向きへ歩きます。ベルトに乗ったままでは1.6秒以内に足場の外へ出る位置では攻撃を始めず、ためや前隙の途中で1秒以内になったら取り消します。相手がいない間（相手の復帰待ち）も、ベルトの上にいれば中央（セーフゾーンが有効ならその中心）へ歩いて降ります。
- **投げ（つよい、遺跡・回廊）:** 投げた相手が落ちる向き（16方向のうち、投げの距離の先に床がなく、床の切れ目が最も近い向き）へ投げます。穴も場外も同じ扱いです。なければセーフゾーンの外へ投げます。

タイトル画面の対戦設定では、CPUの枠の行ごとに強さを上書きできます（`MatchOptions.overrides`、キーはキャラクターのID 1〜3）。上書きのないCPU（「おまかせ」）は全体の強さ（`MatchOptions.difficulty`）に従います。対戦設定（操作の割り当て `controls` を含む）はブラウザーの `localStorage`（キー `bramble.match.v1`）に保存し、壊れた値や範囲外の値は項目ごとに初期値へ戻します。`controls` は重複した機器や不明な値を捨て、枠0を必ず埋めます。試合を始めた設定は、「はじめから」や「もう一度、勝負」でもそのまま使い、そのたびにパッドの接続を確認し直します。稽古のCPUの相手はどの強さでも動きません。

## 10. 実装と検証の境界

シミュレーションは1/60秒の固定更新です。描画と入力は別モジュールに分け、描画フレーム間の短いボタン入力も次のシミュレーション更新まで保持します。WebGL、モーション、効果音、パッドの振動は戦闘結果の計算を担当しません。

カメラは足場を斜めに見下ろす透視カメラで、向きは常に一定です。視点の自動追随が動かすのは注視点と距離だけなので、画面上の方向と地面上の方向の対応は変わりません。キー、タッチのスティック、ゲームパッドのスティック、矢印キーの照準は画面上の方向として受け取り、入力モジュールが [`src/game/coordinates.ts`](../src/game/coordinates.ts) のカメラの向きを使って地面上の方向に変換してから、シミュレーションへ渡します。DIの移動入力も同じ変換を通ります。マウス照準はカーソル位置を地面上の点に変換して狙います。シミュレーションが扱うのは常にワールド座標の方向で、この文書の角度や距離はすべてワールド座標の値です。

### 入力とプレイヤー

[`src/game/input.ts`](../src/game/input.ts) の `BattleInput.sample(state)` は、描画フレームごとに、試合のプレイヤーのキャラクター1人につき1つの `PlayerInput` を返します（`PlayerInputs`、キーはキャラクターのID）。どの機器がどのキャラクターを操作するかは `MatchOptions.controls`（第9節）で決まります。キーボードの枠はキーボードとマウス、またはタッチ操作から、パッドの枠はそのパッドから入力を作ります。キーボードの枠がない試合では、キーボードの操作キーとタッチ操作を無効にします（`Esc` の一時停止と `V` の視点切り替えは使えます）。入力を受け付けるのは、ダイアログが開いていない `countdown` と `playing` の間だけです。受け付けを始めた時点で押されているパッドのボタンは押下済みとして扱い、離すまで反応しません（メニューで押した `A` や `Start` が試合に漏れません）。

`BattleEngine.update(dt, inputs)` は `PlayerInputs` を受け取ります。マップに入力のないプレイヤーは空の入力（立ち止まる）として扱います。`PlayerInput` を単体で渡すと、最初のプレイヤーの入力とみなします（1人の試合とテストではこれで足ります）。押した瞬間の入力（攻撃・ジャンプ・ステップ・キャンセル・つかみ）はプレイヤーごとに保持し、固定更新が1回消費するまで残します。消費した後は、同じ描画フレームの残りの更新へ持ち越しません。一時停止中とメニューでは保持中の入力を捨てます。

### ゲームパッド

[`src/game/pads.ts`](../src/game/pads.ts) の `PadHub` は、描画フレームごとに1回 `navigator.getGamepads()` の0〜3番（パッド1〜4）を読んで値をコピーし、試合の入力、メニュー操作、タイトルの参加操作に配ります。接続の変化を通知し、振動の再生（`vibrationActuator.playEffect("dual-rumble")`、未対応なら何もしない）も担当します。ボタンの割り当ては [`src/game/gamepad.ts`](../src/game/gamepad.ts) の純粋な関数で、DOMを使わないのでnodeのユニットテストで検証できます。配置は標準ゲームパッド配置（Xbox系の表記）です。

| 定数                              | 値              | 意味                                                                                                                                 |
| --------------------------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `DEAD_ZONE`                       | 0.2             | 両スティックの円形デッドゾーン。内側は0、外側はデッドゾーンの縁が0、最大の傾きが1になるよう伸ばす（長さは1を超えない）               |
| `TRIGGER_THRESHOLD`               | 0.5             | `LT`・`RT` はアナログ値がこれ以上で押下。ほかのボタンは `pressed` か、値がこれ以上で押下                                             |
| `FLICK_THRESHOLD` / `FLICK_REARM` | 0.7 / 0.3       | 右スティックの横成分が0.7を超え、縦成分より大きいと相手切替。傾きが0.3未満に戻るまで次の切替を受け付けない（どちらも伸ばした後の値） |
| `NAV_DELAY` / `NAV_INTERVAL`      | 0.38秒 / 0.13秒 | メニューで方向を押し続けたときのリピート。1回目はすぐ、0.38秒後から0.13秒ごと                                                        |

- 割り当て（`ATTACK_BUTTONS` と `readPad`）: `RB` 横振り、`RT` 振り下ろし、`LB` 突き、`LT` 振り上げ、`A` ジャンプ、`B` ステップ、`X` つかみ、`Y` キャンセル、`R3` ロックオン、十字キー左右で相手切替、`View` 視点、`Start` 一時停止。左スティックは移動、右スティックはロックオン解除中の照準です。十字キーでは移動せず、上下は試合中は何もしません。
- 押した瞬間は前のフレームとの比較で1回だけ出ます。攻撃は押し続けている技も返すので、押し続けるとためになります。複数の攻撃ボタンを押しているときは最後に押した技、同時に押したときは `RB`・`RT`・`LB`・`LT` の順で最初の技です。
- 短い配列や数値でない値は、離したボタンと中央のスティックとして読みます。
- 一時停止と視点: `Start` は試合のキャラクターを操作しているパッドからだけ一時停止します。`View` はどのパッドからでも、共有の視点設定（視点の自動追随）を切り替えます。一時停止中の再開はメニュー側が受け持ちます。
- 切断: 試合中（一時停止中を含む）に試合のキャラクターを操作しているパッドが外れると、一時停止して、一時停止画面にどのパッドかを表示します。同じ切断は1回だけ報告します。パッドの接続が変わると表示を消しますが、再開はプレイヤーが行います。
- メニュー（[`src/ui/padMenu.ts`](../src/ui/padMenu.ts)）は接続中のどのパッドでも動きます。十字キーか、半分以上倒した左スティックで、その方向で最も近い操作部品へフォーカスを移します（選択欄は左右で値を変えます）。`A` は決定、`B` は戻る（一時停止では再開、ダイアログでは閉じる）、`Start` はタイトルで開始、一時停止で再開、結果画面で再戦です。画面が切り替わった時点で押されているボタンと方向は、離すまで反応しません。タイトルでは、どの枠にもいないパッドの `A`・`Start` を参加（`joinPad`、最初のCPUの枠へ）に、枠0以外に入っているパッドの `B` を退出（`leavePad`）に先に使います。選んだ機器がほかの枠で使われていれば、2つの枠の機器を入れ替えます（`assignDevice`）。
- 振動: `rumbleFor` がキャラクターの状態を前のフレームと比べて決めます。ヒットストップが新たに増えたフレームだけが対象で、そのときの状態が `hitstun`（攻撃を受けた）なら強さ `0.35 + 増えた% / 30`（1が上限）で約170〜280ミリ秒（`110 + 170 × 強さ`）、`clash`（相殺）なら150ミリ秒、`active` か `recovery`（攻撃を当てた）なら最も弱い90ミリ秒です。ヒットストップが減っていく間と何も起きないフレームは振動しません。パッドで操作しているキャラクターにだけ出し、グラフィック設定の `padRumble`（パッドの振動）がオフなら出しません。

### ロックオン

ロックオンは入力側だけの仕組みです。`BattleInput` がプレイヤーのキャラクターごとに（キャラクターのIDをキーに）オン・オフと狙う相手を持ち、オンの間は毎フレーム、そのキャラクターから狙う相手への方向を照準としてシミュレーションへ渡します。シミュレーションが受け取るのはマウス照準と同じ照準ベクトルだけなので、第2節の旋回速度の制限はそのまま働き、向きが瞬時に相手へ合うことはありません。

- ページを開いたときはオンです。切り替えた状態はページを開いている間、同じ枠の次の試合にも引き継ぎます。
- 狙う相手の選び方は [`src/game/lockOn.ts`](../src/game/lockOn.ts) にあります。候補は自分以外で退場していない（復帰待ちでない）キャラクターです。狙っている相手が候補にいる限り、ほかの相手が近くても変えません。候補から外れたら最寄りの候補へ移ります（同距離ならIDの小さい方）。試合の開始時とオンにした直後も最寄りの候補を選びます。
- 相手切替は、画面上でプレイヤーから見た現在の相手の方位から、時計回り（次）または反時計回り（前）に最も近い候補へ移ります。候補が1人なら何もしません。
- 入力: オン・オフは `Tab`、マウス中ボタン、ゲームパッドの `R3`。次の相手は `E`、マウスホイール下、十字キー右、右スティックを右へ弾く操作。前の相手はホイール上、十字キー左、右スティックを左へ弾く操作。ホイールは0.18秒に1回まで、右スティックは中央付近（`FLICK_REARM`）へ戻すまで次の切替を受け付けません。タッチ操作にはオン・オフの切り替えがなく、乱闘でだけ「相手切替」ボタン（次の相手）を表示します。
- オフの間の照準は、キーボードの枠では矢印キー、マウスカーソルの地面上の位置の順に優先し、パッドの枠では右スティックを使います。どれもなければ移動方向を向きます。
- HUDは狙われている相手のカードにチップを表示します。プレイヤーが1人なら `LOCK`、複数なら狙っている人を `P1 LOCK` のようにその人の色で示し、同じ相手を複数人が狙えばチップを並べます。3D画面の相手には何も描きません。

表示側の処理は、シミュレーションの状態を読んで作るだけで、何も書き戻しません。関節付きのリグとアニメーション（[`src/render/motion.ts`](../src/render/motion.ts)）は、各キャラクターの状態、技、状態時間、ため量、速度から毎フレームのポーズを決め、ヒットストップ中はシミュレーションと同じくポーズを止めます。剣の軌跡、床の土煙・ひび・火花、命中と相殺で飛び散る火花・静電気のような稲妻・閃光、空中回避の宙返り、復帰後の無敵中の点滅、カメラの揺れ、剣の効果音（風切り、打ち込み、攻撃確定、ため）、パッドの振動も同じ状態や状態の変化から作ります。キャラクターの上の表示は、プレイヤーが1人なら `YOU`、複数なら `P1`・`P2`…（各キャラクターの色）、CPUなら名前と%です。HUDのカードの表示も同じ規則です。視点の自動追随は、退場していないキャラクターを画面に収める注視点と距離を毎フレーム求め、近くに集まると寄り、離れるかオフにすると足場全体の固定視点へ滑らかに戻ります。描画上の剣の位置は判定を決めません。判定は第3節の技ごとの範囲で計算し、モーションはその範囲に合わせて作っています。グラフィック設定（解像度、アンチエイリアス、影、FPS上限、画面の揺れ、視点の自動追随など）は描画だけを変え、1/60秒の更新間隔、数値、判定は変わりません。

ユニットテストでは、状態遷移、消費、無敵区間、前隙中の旋回、空中回避、同一攻撃の再命中防止、相殺の処理順、DI、空中復帰の回数、拘束解除、フィールド縮小、エリア外ゲージ、爆撃などを検証します。残機と復帰（復帰位置、無敵時間、勝敗と制限時間、復帰待ちが攻撃や狙いの対象外であること）、CPUの強さごとの数値と行動の違い、ふつうが従来のCPUを再現すること、ロックオンの対象選択と相手切替、対戦設定の保存と補正もユニットテストの対象です。ローカル対戦では、モードと `controls` ごとの `human` と `player`、複数のプレイヤーが独立して動きCPUも動き続けること、入力のないプレイヤーが立ち止まること、単体の入力が最初のプレイヤーだけを動かすこと、プレイヤーごとの押下の保持と1回だけの消費、スタミナ不足の通知が1人のときだけ出ること、復帰と稽古の作り直しの後もプレイヤーのままであること、プレイヤーとCPUが混ざった勝敗を検証します（`tests/multiplayer.test.ts`）。操作の入れ替え・参加・退出・未接続のパッドの扱い（`tests/matchStore.test.ts`）と、パッドの割り当て・トリガーのしきい値・デッドゾーン・右スティックの弾き・不正な配列・メニューのリピート・振動の条件（`tests/gamepad.test.ts`）も対象です。表示側も、画面方向から地面上の方向への変換、描画上の剣が各技の判定範囲を通ること、ヒットストップ中のポーズの停止、空中回避の宙返り、剣の効果音の発生条件、グラフィック設定の保存と補正をユニットテストで確認します。PlaywrightのE2E（2ファイル・7テスト）では、実際の起動、操作（空中回避を含む）、HUD、対戦設定を反映したCPU戦と設定の保持、ロックオンと自由な照準の切り替え、視点の切り替え、落下と復帰、タッチ画面、グラフィック設定の反映と保持を確認します。`e2e/multiplayer.spec.ts` は `navigator.getGamepads` を偽のパッドに置き換え、タイトルでの参加・退出・操作の入れ替え、キーボードとパッドの2人による一騎打ち（`P1`/`P2` と `P2 LOCK` の表示、別々の移動と攻撃、`Start` の一時停止と再開、切断時の一時停止と通知、別のパッドでの再開）を確認する構成です。

調整するときは、まず一騎打ち・稽古で「避けた後に反撃が間に合うか」「ためキャンセルで回避を誘えるか」「攻撃と回避の連打がスタミナで抑えられるか」を確認します。乱闘と環境ギミックが加わったときに、位置取りの判断が残るかを続けて見ます。
